# United MFL

Сайт и админ-панель медиа-футбольной лиги United MFL.

| Папка | Что внутри | Стек |
|---|---|---|
| `backend/` | API, база, live-трансляция (SSE), распознавание протоколов матчей (PDF → текст, фото → OCR) | Go 1.24, chi, PostgreSQL |
| `web/` | Публичный сайт (узбекский язык, светлая тема) | Next.js 15, SSR |
| `admin/` | Админ-панель и мобильный Live-пульт | React 19 + Vite |
| `register/` | Отдельный сайт регистрации команд (открывается из админки) | React 19 + Vite |
| `deploy/` | Продакшен: Postgres + API + сайт + Caddy (HTTPS, админка) | Docker Compose |

## Быстрый запуск на сервере

```bash
curl -fsSL https://raw.githubusercontent.com/sanedidi/unitedmfl/main/deploy/deploy.sh | sudo bash
```

Скрипт ставит Docker (если его нет), клонирует репозиторий в `/opt/unitedmfl`, создаёт `deploy/.env` со случайными секретами и первым администратором (логин и пароль сохраняются в `deploy/FIRST_ADMIN.txt`) и поднимает контейнеры. Повторный запуск того же скрипта обновляет код и пересобирает контейнеры.

Стек работает за nginx, который уже установлен на сервере: Caddy внутри Docker слушает только порты 8120 (сайт), 8121 (админка) и 8122 (регистрация команд). Пока домены не настроены, сайт открывается на `http://IP:8120`, админка — на `http://IP:8121`, регистрация — на `http://IP:8122`.

Как подключить домены:
1. Скопируйте `deploy/nginx.conf.example` в `/etc/nginx/sites-available/unitedmfl` и впишите свои домены.
2. Выполните `nginx -t && systemctl reload nginx`, затем `certbot --nginx -d … -d …`.
3. В `deploy/.env` замените привязку портов на `127.0.0.1:8120` / `127.0.0.1:8121`, а `PUBLIC_BASE_URL` — на `https://домен`.
4. Перезапустите `deploy.sh`.

Резервные копии (база и загруженные файлы): `deploy/backup.sh`. Пример строки для cron есть внутри скрипта.

## Локальная разработка

```bash
# 1. API (нужен Postgres; данные сезона 2026 добавляются миграциями)
cd backend
DATABASE_URL=postgres://user:pass@localhost:5432/unitedmfl?sslmode=disable \
ADMIN_EMAIL=admin@local.test ADMIN_PASSWORD=change-me-123 \
go run -mod=vendor ./cmd/api              # :8080

# 2. Сайт
cd web && npm ci && API_INTERNAL_URL=http://localhost:8080 npm run dev     # :3000

# 3. Админка
cd admin && npm ci && API_URL=http://localhost:8080 npm run dev            # :5173

# 4. Сайт регистрации команд (API запускайте с REGISTER_PUBLIC_URL=http://localhost:5174)
cd register && npm ci && API_URL=http://localhost:8080 npm run dev         # :5174
```

Тесты: `cd backend && go test -mod=vendor ./...`.

## Как устроено

- **Сайт** рендерится на сервере при каждом запросе: всегда свежие данные из API. Страница матча подключается к `/api/v1/live/{id}` (SSE), поэтому счёт и события обновляются без перезагрузки.
- **Админка** — SPA на отдельном адресе. Запросы к `/api` идут на тот же origin (их проксирует Caddy). Авторизация: JWT access-токен плюс ротируемый refresh-токен. Роли: администратор, редактор, оператор матча, менеджер магазина.
- **Протоколы матчей.** Загрузка → распознавание → проверка в админке (спорные поля подсвечены) → «Применить». После применения обновляются счёт, события, составы, судьи и таблица; по желанию PDF публикуется на странице матча.
- **Live-пульт** (`/live` в админке) рассчитан на телефон. Если пропадает интернет, события копятся в очереди на устройстве и отправляются, когда связь вернётся; повторы отсекаются по `Idempotency-Key`.
- **Таркиблар (составы).** В карточке матча в админке — редактор состава: схема (4-3-3, 4-2-3-1 и др.), перетаскивание игроков на поле и в запас, капитан, номера, тренеры. Черновик сохраняется автоматически; на сайт состав попадает только после «E’lon qilish», и сервер не даст опубликовать состав с ошибками (нет вратаря, повтор номера, лишние игроки и т.п.). Составы из протокола публикуются сразу, без схемы — на сайте они показываются списком. В Live-пульте вкладка «Tarkib» показывает текущий состав, оформляет замены и смену схемы по ходу матча — на сайте «Joriy tarkib» обновляется в реальном времени. Лимит запасных — `LINEUP_BENCH_MAX` (по умолчанию 9). Тренерский штаб и пакетная загрузка фото игроков — в карточке команды.

## Регистрация команд

Команды подают заявку сами, на отдельном сайте (`register/`, порт 8122, домен вида `ariza.unitedmfl.uz`). **Сайт закрыт, пока админ не откроет приём:** без активной ссылки он показывает «Ro‘yxatdan o‘tish hozircha yopiq».

**Как открыть приём.**
1. Админка → «Arizalar» → «Yangi havola».
2. Указать сезон, срок, лимит команд и требования.
3. Включить «Qabul ochiq». Ссылка вида `https://ariza…/K7M2QX` появится в карточке: её можно скопировать, скачать QR-код или отправить в Telegram.
4. По желанию включить «Asosiy sahifada ko‘rsatish», чтобы приём открывался и на главной странице сайта регистрации.

**Как закрыть приём.** Выключить «Qabul ochiq». Также ссылка закрывается сама, когда:
- истёк срок;
- набран лимит команд;
- одноразовая ссылка уже использована.

«Havolani yangilash» выдаёт новый код, и старая ссылка перестаёт работать.

**Что заполняет представитель** (4 шага, черновик сохраняется автоматически):
1. **Команда:** название, короткий код, логотип, цвета формы.
2. **Представитель:** телефон с SMS-кодом (если SMS настроены), Telegram.
3. **Состав.** Поля как в `TARKIB.xlsx`: имя и фамилия, надпись на футболке, дата рождения, номер, размер формы, место работы, роль (полевой игрок, вратарь, медиа-персона), фото, медсправка. Сюда же входят тренер и раздел «Media shaxslar». Готовый `TARKIB.xlsx` загружается целиком: колонки «No-12» и GK/Media/Coach распознаются, «2Xl» превращается в 2XL, повторы номеров и перепутанные имя и фамилия подсвечиваются, картинку из файла можно сделать логотипом.
4. **Проверка** и отправка.

После отправки по той же ссылке `/a/{token}` открывается страница статуса.

**Проверка в админке** («Arizalar» → заявка) показывает автопроверку, историю и сводку размеров формы, заявку можно выгрузить в `TARKIB.xlsx`. Варианты решения:
- **«Tasdiqlash».** Создаются команда, игроки (с размером, надписью, датой рождения, медсправкой) и тренерский штаб. Игрока, который уже есть в другой команде, можно перенести со всей статистикой.
- **«Tuzatishga qaytarish».** Представителю открываются только отмеченные разделы, с комментариями и сроком. Если срок истёк, заявка отклоняется автоматически.
- **«Rad etish».** Заявка отклоняется с причиной.

Доступ: право «Jamoa arizalari» (роли «Administrator» и «Muharrir»).

**Настройки в `deploy/.env`:**
- `REGISTER_BIND` — адрес и порт;
- `REGISTER_PUBLIC_URL` — публичный адрес сайта регистрации, из него админка строит ссылки;
- `REGISTER_HELP_URL` — ссылка «Yordam»;
- `ESKIZ_EMAIL`, `ESKIZ_PASSWORD`, `ESKIZ_FROM`, `SMS_CODE_TEXT` — SMS-коды через notify.eskiz.uz. Текст должен совпадать с одобренным в Eskiz шаблоном. Без этих переменных подтверждение телефона выключено. При локальной разработке код показывается прямо на странице.

Медсправки хранятся в `/data/uploads/applications/<id>/` и отдаются только по ссылке представителя или авторизованному админу.

Тест сценария целиком (нужен Postgres): `TEST_DATABASE_URL=postgres://… go test -mod=vendor -run TestTeamRegistration ./internal/api/`.

## Telegram Live-пульт

Бот дублирует мобильный Live-пульт в Telegram: оператор выбирает матч, начинает его, ставит перерыв и завершает, записывает голы, карточки, замены, пенальти и серию пенальти, удаляет ошибочные события. Сайт обновляется сразу, как и из веб-пульта.

**Доступ — только по номеру телефона.**
1. Администратор открывает «Foydalanuvchilar», выбирает пользователя с ролью «Match operatori» или «Administrator» и заполняет поле «Telefon (Telegram Live-pult)».
2. Оператор открывает бота, нажимает /start и «📱 Telefon raqamni yuborish».
3. Бот пускает, только если Telegram прислал собственный номер этого аккаунта и номер совпадает с карточкой активного пользователя. Всем остальным бот отвечает «⛔ Ruxsat yo‘q».

Если очистить или изменить номер, заблокировать пользователя или сменить ему роль, доступ пропадает при следующем нажатии. Привязанные аккаунты помечены в списке пользователей бейджем «Telegram».

**Как устроено.** Бот работает внутри Go API (`backend/internal/tgbot`), получает обновления через long polling (вебхук и открытый порт не нужны). Действия выполняются через те же обработчики API от имени оператора. Поэтому валидация, журнал действий, SSE-трансляция и сброс кэша сайта работают так же, как в веб-пульте. Повторное нажатие на ту же кнопку не создаёт дубль: используется `Idempotency-Key`.

**Включение.** Впишите токен от @BotFather в `deploy/.env` (`TELEGRAM_BOT_TOKEN=…`) и перезапустите `deploy.sh`. Токен не коммитится: репозиторий публичный. При пустом токене бот выключен. Можно запускать только один экземпляр API с этим токеном: Telegram не отдаёт обновления двум получателям одновременно.

Тест сценария целиком (нужен Postgres): `TEST_DATABASE_URL=postgres://… go test -mod=vendor ./internal/tgbot/`.

## Instagram на странице Media

Страница `/media` показывает 12 последних постов Instagram-аккаунта лиги (на телефоне — 8). Используется официальный Instagram API with Instagram Login (`graph.instagram.com`).

**Как устроено.** Go API раз в 30 минут (`INSTAGRAM_SYNC_MIN`) забирает последние 24 поста, копирует картинки в `/uploads/images/ig-<id>.*` и при изменениях сбрасывает кэш сайта. Ссылки Instagram CDN временные, поэтому сайт показывает только свои копии. Посты, удалённые в Instagram, пропадают и с сайта. Долгоживущий токен (60 дней) API продлевает сам, когда до конца срока остаётся меньше 20 дней. Код: `backend/internal/api/instagram.go`, блок сайта — `web/src/components/InstagramFeed.tsx`.

**Токены.** Принимаются два вида:
- `IGAA…` — токен Instagram User (graph.instagram.com, 60 дней, продлевается автоматически);
- `EAA…` — токен Facebook Graph (graph.facebook.com). Новые приложения Meta получают его через «API setup with Unified login» как бессрочный токен системного пользователя. Instagram-аккаунт находится сам через страницы токена, или его ID указывают вручную.

**Подключение (текущее приложение Meta «United MFL Site», ID 1828147875097772, портфолио «United mfl»).**
1. Instagram-аккаунт должен быть профессиональным (Business или Creator) и иметь роль «Тестировщик Instagram» в приложении (Роли в приложении).
2. Сценарии использования → Instagram API → «API setup with Unified login» → шаг 1: конфигурация; шаг 2: «Сгенерировать маркер» у аккаунта → скопировать токен.
3. Админка → «Instagram» → вставить токен → «Ulash». Там же можно скрыть отдельные посты, обновить ленту вручную или отключить Instagram.

Тест синхронизации (нужен Postgres): `TEST_DATABASE_URL=postgres://… go test -mod=vendor -run Instagram ./internal/api/`.

## Дизайн

Сайт и админка следуют макету Figma «United MFL — Pro Design System (Site + Admin)»: светлые нейтральные поверхности, графитовые hero и подвал, один лаймовый акцент `#91DA27`, радиусы 2–8 px, прямоугольные бейджи. Шрифты Archivo (заголовки, счёт) и Inter (интерфейс, таблицы) лежат в репозитории и отдаются со своего сервера, без Google Fonts. Токены сайта — в `web/src/app/globals.css`, админки — в `admin/src/styles.css`.

- Логотип в коде — векторная перерисовка знака лиги (`web/src/components/Logo.tsx`). Когда лига пришлёт официальный SVG, достаточно заменить пути в `LogoMark`.
- Эмблемы клубов нейтральные (инициалы на сером круге), пока в админке не загружены официальные файлы (`crest_url`).
- Русская и английская версии сайта отмечены в меню как «tez orada».

## Что нужно подтвердить у лиги

- Очки 3/1/0 и порядок тай-брейков: сейчас очки → разница мячей → забитые. Значения очков задаются в `.env`.
- Составы групп. На сайте лиги группы не опубликованы, поэтому они помечены как предварительные.
- Формат составов: сейчас 11 в старте и до 9 запасных (как в протоколе). Публиковать состав могут администратор и оператор матча; редактору это недоступно.
- Отметки «T» в колонке «A» протокола: сейчас они трактуются как удар в серии пенальти.

## SEO

- **Адреса страниц.** У матчей и игроков человекочитаемые адреса: `/matchlar/13-andijon-mobiuz-2026-09-15`, `/oyinchilar/5-imeda-ashortia`. Адрес матча не меняется до игры, во время и после неё. Старые и неточные адреса (`/matchlar/13`) отвечают постоянным редиректом 308 на правильный.
- **Метаданные.** У каждой страницы уникальные `title` и `description`, canonical, Open Graph и Twitter Card (`src/lib/seo.ts`). Для главной, матчей и команд картинки соцсетей генерируются автоматически (`opengraph-image.tsx`). Страницы с фильтрами и поиск закрыты от индексации (`noindex, follow`) и указывают canonical на основной список.
- **Структурированные данные (JSON-LD).** SportsOrganization, WebSite, SportsEvent, SportsTeam, Person, NewsArticle, Product, VideoObject и BreadcrumbList. Заполняются только реальными данными.
- **Sitemap.** `/sitemap.xml` — индекс, ссылающийся на `/sitemaps/{pages,matches,teams,players,news,merch}.xml`. Большие разделы делятся на файлы по 10 000 адресов. Дата `lastmod` берётся из `updated_at` в базе (`GET /api/v1/sitemap`).
- **Кэш.** Страницы рендерятся на сервере при каждом запросе, а ответы API кэшируются в Next.js (15–300 с). Любое изменение в админке сразу сбрасывает этот кэш: Go вызывает `POST /internal/revalidate` с секретом `REVALIDATE_SECRET`.
- **Подтверждение прав и аналитика.** Задаются в `deploy/.env`: `GOOGLE_SITE_VERIFICATION`, `YANDEX_VERIFICATION`, `BING_SITE_VERIFICATION`, `GA_MEASUREMENT_ID`. Если `GA_MEASUREMENT_ID` указан, Core Web Vitals реальных посетителей отправляются в GA4.
- **Проверка.** `cd web && BASE=http://localhost:3000 npm run test:seo` обходит весь sitemap и проверяет:
  - коды ответов и редиректы, настоящие 404;
  - title, description, canonical, Open Graph, `noindex`;
  - JSON-LD, ровно один H1 на странице;
  - внутренние ссылки, robots.txt.
