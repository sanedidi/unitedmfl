# United MFL

Сайт и админ-панель медиа-футбольной лиги United MFL.

| Папка | Что внутри | Стек |
|---|---|---|
| `backend/` | API, база, live-трансляция (SSE), распознавание протоколов матчей (PDF → текст, фото → OCR) | Go 1.24, chi, PostgreSQL |
| `web/` | Публичный сайт (узбекский язык, тёмная тема) | Next.js 15, SSR |
| `admin/` | Админ-панель и мобильный Live-пульт (светлая тема) | React 19 + Vite |
| `deploy/` | Продакшен: Postgres + API + сайт + Caddy (HTTPS, админка) | Docker Compose |

## Быстрый запуск на сервере

```bash
curl -fsSL https://raw.githubusercontent.com/sanedidi/unitedmfl/main/deploy/deploy.sh | sudo bash
```

Скрипт ставит Docker (если его нет), клонирует репозиторий в `/opt/unitedmfl`, создаёт `deploy/.env` со случайными секретами и первым администратором (логин и пароль сохраняются в `deploy/FIRST_ADMIN.txt`) и поднимает контейнеры. Повторный запуск того же скрипта обновляет код и пересобирает контейнеры.

Стек работает за nginx, который уже установлен на сервере: Caddy внутри Docker слушает только порты 8120 (сайт) и 8121 (админка). Пока домены не настроены, сайт открывается на `http://IP:8120`, а админка — на `http://IP:8121`.

Как подключить домены:
1. Скопируйте `deploy/nginx.conf.example` в `/etc/nginx/sites-available/unitedmfl` и впишите свои домены.
2. Выполните `nginx -t && systemctl reload nginx`, затем `certbot --nginx -d … -d …`.
3. В `deploy/.env` замените привязку портов на `127.0.0.1:8120` / `127.0.0.1:8121`, а `PUBLIC_BASE_URL` — на `https://домен`.
4. Перезапустите `deploy.sh`.

Резервные копии (база и загруженные файлы): `deploy/backup.sh`. Пример строки для cron есть внутри скрипта.

## Локальная разработка

```bash
# 1. API (нужен Postgres; данные сезона 2026 добавляются миграциями)
cd backend
DATABASE_URL=postgres://user:pass@localhost:5432/unitedmfl?sslmode=disable \
ADMIN_EMAIL=admin@local.test ADMIN_PASSWORD=change-me-123 \
go run -mod=vendor ./cmd/api              # :8080

# 2. Сайт
cd web && npm ci && API_INTERNAL_URL=http://localhost:8080 npm run dev     # :3000

# 3. Админка
cd admin && npm ci && API_URL=http://localhost:8080 npm run dev            # :5173
```

Тесты: `cd backend && go test -mod=vendor ./...`.

## Как устроено

- **Сайт** рендерится на сервере при каждом запросе: всегда свежие данные из API. Страница матча подключается к `/api/v1/live/{id}` (SSE), поэтому счёт и события обновляются без перезагрузки.
- **Админка** — SPA на отдельном адресе. Запросы к `/api` идут на тот же origin (их проксирует Caddy). Авторизация: JWT access-токен плюс ротируемый refresh-токен. Роли: администратор, редактор, оператор матча, менеджер магазина.
- **Протоколы матчей.** Загрузка → распознавание → проверка в админке (спорные поля подсвечены) → «Применить». После применения обновляются счёт, события, составы, судьи и таблица; по желанию PDF публикуется на странице матча.
- **Live-пульт** (`/live` в админке) рассчитан на телефон. Если пропадает интернет, события копятся в очереди на устройстве и отправляются, когда связь вернётся; повторы отсекаются по `Idempotency-Key`.

## Что нужно подтвердить у лиги

- Очки 3/1/0 и порядок тай-брейков: сейчас очки → разница мячей → забитые. Значения очков задаются в `.env`.
- Составы групп. На сайте лиги группы не опубликованы, поэтому они помечены как предварительные.
- Отметки «T» в колонке «A» протокола: сейчас они трактуются как удар в серии пенальти.
